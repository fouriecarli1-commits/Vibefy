# Legal artefacts

> **Every document in this directory is a DRAFT.** Drafts are not legal advice and are not a
> substitute for a qualified lawyer in the operating jurisdiction. They exist to make that
> review cheap and fast, not to replace it. Budget for one lawyer review before the first
> paying customer — see `docs/BUSINESS_CHECKLIST.md`.

## Jurisdiction

Written to a **GDPR-grade baseline**, the strictest common standard across the markets under
consideration. A jurisdiction layer (`VIBEFYCODE_JURISDICTION` = `gdpr` | `uae_pdpl` | `za_popia` |
`us`) selects variants of the data-protection clauses without rewriting the documents. The
entity and governing law are not yet decided; every placeholder reading `[JURISDICTION]`,
`[LEGAL_ENTITY]` or `[PRIMARY_DOMAIN]` is resolved before launch, not before building.

## How versions and acceptance work

Each document carries a semantic version and is registered in `legal/registry.json` with a
SHA-256 of its bytes, generated by `pnpm legal:registry`. When a user accepts a document, the
`consents` table records the document type, the version **and that hash** — so "which exact
words did they agree to" is answerable years later even if the file is edited. The `consents`
table is append-only; withdrawal is a new record, never an edit.
